    \chapter{Vorgehensweisen, Materialien und Methoden}
    SaveWorld besteht aus mehreren Komponenten, die alle miteinander interagieren.
    Die beiden Hauptkomponenten sind die App (Frontend) und der Server (Backend).
    Sämtliche Komponenten sind mit der Programmiersprache TypeScript entwickelt, welche ein Super-Set von JavaScript ist
    und die statische Typisierung von Variablen ermöglicht.


    \section{Frontend}
    Das Frontend ist die App, welche die Nutzer verwenden.
    Diese ist mit dem Framework Ionic entwickelt worden, welches die Erstellung von Hybrid-Apps ermöglicht.
    Hybrid-Apps sind Apps, die auf allen gängigen Plattformen laufen, da sie mit Webtechnologien entwickelt werden.
    Die App verwendet die Benutzeroberflächen Bibliothek React mit dem Design Framework Chakra-UI.
    Dieser Aufbau ermöglicht ein reaktives Nutzererlebnis, da sich die App automatisch aktualisiert, wenn sich der Zustand ändert.
    Um mit dem Backend zu kommunizieren, wird eine auf dem REST-Prinzip basierende Programmierschnittstelle f\"ur die Programmiersprache JavaScript verwendet.
    Beim Start der Anwendung verbindet sich die App mittels WebSockets mit dem Backend, um Benachrichtigungen zu empfangen und zu versenden.
    Die Anmeldedaten des Nutzers werden mit dem JSON Web Token Standard gespeichert, um die Authentifizierung zu gewährleisten.
    Sollte der Benutzer angemeldet sein, hat er, je nach Rolle, Zugriff auf verschiedene Funktionen, ansonsten wird er aufgefordert, sich anzumelden.
    Neben der Kommunikation mit dem Backend, kommuniziert die App auch mit dem Feature-Flag-Service Flagsmith, um bestimmte Funktionen zu aktivieren oder zu deaktivieren.


    \section{Backend}
    Das Backend ist die Schnittstelle zwischen der App und der Datenbank.
    Es wurde mit express.js entwickelt und bietet neben der REST-API auch eine WebSocket-Schnittstelle an,
    welche für die Echtzeit Kommunikation im Forum verwendet wird.
    F\"ur die Speicherung von Daten wird eine MongoDB Datenbank verwendet.
    S\"amtliche hochgeladenen Dateien, wie Profilbilder, werden in einem S3-kompatiblen Object Storage gespeichert.
    Um Push-Benachrichtigungen an die App zu senden, wird der Dritt-Anbieter OneSignal verwendet.
    Um einen Benutzer zu authentifizieren, wird einmalig das Passwort benötigt, welches gehasht, das heißt
    kryptografisch so verändert wird, dass es nicht mehr umkehrbar ist, in der Datenbank gespeichert wird.
    Nach der Authentifizierung wird ein JSON Web Token an den Client gesendet, welcher für die weitere Kommunikation verwendet wird.
    Hierbei wird in dem Token lediglich die Benutzer-ID gespeichert, sodass der Server den Benutzer identifizieren kann und es nicht zu Problemen bei der Synchronisation der Daten kommen kann.


    \section{Inhalte}\label{sec:minhalte}
    Dadurch, dass die App von den Inhalten lebt, bestand unser Vorgehen neben dem technischen Aspekt aus intensiver Recherchearbeit.
    Der wichtigste Schritt war dabei die Ideenfindung im Team, in der Themen gesammelt wurden.
    Danach wurden die Themen unterschiedlichen Oberkategorien zugeordnet, um eine bessere Übersicht zu erhalten.
    Diese sind: Mobilität, Kochen, Ernährung, Freizeit, Haushalt, Einkauf, Urlaub und Kleidung.
    Als Recherche-Quellen wurden neben dem Internet auch analog publizierte Medien verwendet.
    Bei der Recherche wurde entschieden, in welchem Format (Video oder Artikel) das Thema am besten präsentiert werden kann.
    Darauf aufbauend wurde es nutzerorientiert aufbereitet, so wurde zum Beispiel die Sprache dem Format angepasst.


    \section{Infrastruktur und Softwareverteilung}
    Das Konzept von SaveWorld sieht vor, bestimmte Funktionen auf verschiedene Server zu verteilen, damit die Last besser verteilt werden kann, sodass die App auch bei vielen Benutzern noch schnell läuft.
    So wird beispielsweise die Datenbank auf einem eigenen Server bereitgestellt, um die Daten von der App zu trennen.
    Ebenfalls werden verschiedene Funktionen zu Drittanbieter Projekten ausgelagert, um die Entwicklung zu beschleunigen.
    Dies betrifft folgende Funktionen:
    \begin{itemize}
        \item \textbf{Geo-Daten}: Die Geo-Daten werden von einer selbst gehosteten Instanz von Nominatim bereitgestellt.
        \item \textbf{Artikel-Verwaltung}: Die Artikel werden mit dem Open-Source Content-Management-System Directus verwaltet.
        \item \textbf{Karten}: Die Darstellung von Karten wird mittels Apple Maps realisiert.
        \item \textbf{Push-Benachrichtigungen}: Die Push-Benachrichtigungen werden von OneSignal bereitgestellt.
        \item \textbf{Feature-Flags}: Die Feature-Flags werden von Flagsmith verwaltet.
    \end{itemize}
    Alle weiteren Funktionen der Anwendung wurden mit Ausnahme der Open-Source Bibliotheken selbst entwickelt.


    \section{Probleme}
    Zu Problemen kam es vor allem bei der Integration von OneSignal, da das Signieren
    der App für den Apple App Store nicht mit dem zuvor verwendeten Signierungsverfahren
    kompatibel war.
    Des Weiteren gab es Schwierigkeiten bei der Auswahl des Inhalts-Verwaltungs-Systems,
    da die meisten Systeme nicht mit den Ansprüchen von SaveWorld übereinstimmten.
    Hierbei war vor allem die Anforderung, dass das System eine gut dokumentierte API
    bereitstellen muss, um die Inhalte in der App anzeigen zu können, ein Problem.
    Ebenfalls gab es ursprünglich Probleme bei der Auswahl des App-Frameworks, da nicht von
    Anfang an klar war, ob die App für iOS und Android oder nur für eine der beiden Plattformen entwickelt werden sollte.
    Im Laufe der Entwicklung gelang es uns allerdings alle aufgetretenen Probleme zu lösen.
